# 4WS7：0.70m/s、2.00m/s²独立离线固件候选

日期：2026-10-23。**仅离线源码/构建/单元及合成模型验证。未刷写、未连接执行器、未启动实车。**

本目录不在原固件默认目标中；原矩形、4W20、4WGD、ESP32/Tenda及已验收Sign操作台未改。
`upstream.json`固定366个原源码/入口/镜像，CMake发现漂移即停止。
离线脚本还交叉核对上次迁移审查保留清单，去重共383个受保护文件。
不把工作区镜像当作当前在线实板身份，本轮没有重新读板。

## 改了什么

1. **唯一正常目标斜坡在车体SI向量层。** 100Hz按实际dt限制平移速度向量差的欧氏范数，
   不分别给x/y各2m/s²而在对角得到2.83m/s²。航向上限0.10rad/s、变化率0.40rad/s²。
   之后统一麦轮运动学、共同限幅、已确认CPR转换；正常轮控直接使用该结果。
   `ramp_cps_per_s`不再固定800；16300cps/s只作由最大SI包络导出的末级跳变检查，
   **不是把四轮各自改成16300后宣称实现车体2m/s²**。
2. **单轮换向撤销旧方向驱动，不再叠加800cps/s慢回零。**
   该轮立即进入零输出，原始测速≤100cps、20ms滤波测速≤60cps且零输出连续≥30ms才可授予新方向。
   750ms实测滑行/中立预算不被更新目标、过零或请求抖动刷新；到期整车锁存停车。
   没有增加反向制动或改变00滑行停机，也不能承诺真实高速换向必在750ms内完成。
3. **安全干预后的受限追赶。** 中立结束后若当前需求已变大，单轮按由本档SI加速度和航向变化率导出的
   上限重新追上，不直接从0跳到大轮速。此时诊断给出`rejoining_mask`，不能把安全干预期间的有效轮速
   宣称为精确的整体运动学向量；正常跟随时不叠加第二条800cps/s斜坡。
4. 反馈滤波由50ms改为20ms，仍保留原始反馈超速/方向证据；PWM继续10kHz/整1%量化。
   输出变化率按档位限制，起动补偿仍≤30%、≤500ms。低速抵消轮仍可零输出/被动滚动。
5. 低速前馈`80+0.15×cps`和PI种子保留，并报告饱和掩码；**未做高速实物辨识**。
   对角高需求时该种子可能超过80%输出上限，不能据此保证实车达到0.70m/s，也不擅自提高上限。

每个新会话须先失能零指令＋实测停稳500ms，显式选择一个档，再单独使能；选档本身不使能。

正常停止后可按旧规则停稳、手动重置健康运行额度再准备；真实故障不会被该流程清除。

MCU没有Vicon位置输入，围栏仍应由未来专用电脑入口及监督器执行，本轮没有建立可运行的高速ROS入口。

## 版本、末级输出和默认锁

- 新身份`4WS7`（LE `0x37535734`），诊断184字节、输出权限v2；旧矩形/4W20/4WGD解码器不放宽。
- 保留前100字节诊断、首故障快照及有效目标/授予方向，再增加档位、协调向量、加速度/输出限值、
  饱和及安全追赶状态。独立主机解码器同时验证SI→四轮目标、PWM方向、CCR、当前档位和来源权限。
- 选档使用MC-Link `CONTROL_ENABLE`的独立保留值`0x7000+stage`；旧MCU拒绝非零保留字段，
  新MCU不接受旧格式的使能。常规零保留字段失能仍可断能，旧文本`run`入口在本候选禁用。
  检查的ESP源码对4字节CONTROL载荷透传，CMD_VEL格式不变；**未在真实ESP上验证这条新扩展**。
- 序号、会话、CRC、600ms本地指令租约、30ms最大采样间隔、堵转/反向/超速、绝对150s底层预算和全轮归零保留。
  PC合同仍120s；换向/零目标不重置绝对运动额度。
- 新增相对HELLO的发送/接收时间偏差检查：后续包额外落后≥120ms、超前>60ms、发送时间倒退均拒绝，
  新序号不能替陈旧队列续租。计时回绕测试覆盖。**初始HELLO自身延迟未知，这不是同步时钟的绝对端到端年龄证明。**
  新时间门限尚未经过真实Tenda抖动验收，可能需要定位延迟原因，不能为避免停车随意放宽。
- **默认ARM镜像硬件未放行**：使能在协议层被拒绝，`SERVO_EXECUTION_RELEASED=1`编译会报错。
  只有原生测试目标定义`SERVO_NATIVE_TEST`；把该宏带入ARM构建也会报错。
  因此当前bin是可核查的锁定候选，不是可直接刷入运行的试车固件。解除锁需要后续明确评审/改动，
  不是编辑JSON确认项或改一个命令行参数。没有提供刷写或实车启动命令。

## 离线复现

输出目录必须全新；下面只构建、运行本机测试，不运行ROS节点或打开设备：

```bash
cd /home/PRIMARY_USER/vicon_mecanum_ws
source /opt/ros/jazzy/setup.bash
source /home/PRIMARY_USER/vicon_mecanum_ws/install/setup.bash
python3 stm32/mecanum_f407/candidates/servo_4ws7/run_offline.py \
  --output /tmp/4ws7-review-new --arm --regression
```

验证覆盖15组C控制/协议/合成模型检查（内含7档及9组合成惯性/响应参数），
另有独立的默认锁检查、主机184字节协议/篡改校验、原12个运动配置及矩形本体/起动轨迹回归。
全部使用ASan/UBSan的原生控制测试；合成模型由实际控制器PWM驱动，**没有电流/温度模型**。
测试文件中的反馈、轮速、位移均不能替代实车测量。

目标斜坡测试：直行0→0.70m/s、对角0→约0.699m/s在350ms到达协调目标，
10ms正常平移向量步长≤0.020m/s；20/30ms样本按实际dt限幅。
这是协调目标的时间，不是实际电机或车体加速时间；中立、输出变化率、动力不足和打滑仍可能令实车落后。
旧800cps/s折算同级直行/对角目标约需4.93/6.97s，这部分软件额外延迟已移除。
