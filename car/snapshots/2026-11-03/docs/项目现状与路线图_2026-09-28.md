# Vicon 麦克纳姆小车：项目现状与路线图

更新时间：2026-09-28

## 1. 项目目标

使用 Vicon 提供小车的全局位置和姿态，在 Linux PC 的 ROS 2 中完成目标生成、轨迹跟踪和
安全监督；PC 通过 Wi-Fi 向 ESP32-S3 下发车体速度，ESP32-S3 经 UART 转发给
STM32F407；STM32 完成麦克纳姆轮逆运动学、四轮编码器速度闭环和最终电机安全停机。

```text
Vicon -> vicon_receiver -> /car/pose -> ROS 2 位姿控制器 -> /car/cmd_vel
                                                        |
                                                        v
Linux PC -- UDP/MC-Link --> ESP32-S3 -- UART/MC-Link --> STM32F407
                                                        |
                                                        v
                                  2 x D157B/AT8236 -> 4 x MG310 -> 60 mm麦轮
```

K230D 暂不放在核心闭环中，可在底盘稳定后作为视觉任务扩展。这样不会让相机算法影响
Vicon 闭环和电机安全链路的首次调试。

## 2. 硬件基线

| 模块 | 已确定配置 | 当前边界 |
|---|---|---|
| 主控 | STM32F407VGT6 | 安全 UART 握手固件已烧录；四轮正式固件尚未完成 |
| 无线桥 | ESP32-S3-N16R8 | ESP-IDF v6.1 固件已烧录；原生 USB 用于开发日志 |
| 电机 | 4 x MG310 霍尔编码器电机，1:20，额定 7.4 V | 尚未完成单电机转向、编码器和堵转风险实测 |
| 驱动 | 2 x D157B/AT8236 双路驱动 | 每块驱动两个电机；尚未带载验证 |
| 车轮 | 4 x 60 mm 麦克纳姆轮 | 轮序、滚子方向、轴距和轮距待装配后确认 |
| 动力电池 | 3S 11.1 V、2200 mAh、35C、XT30 | 满电约 12.6 V；首次测试必须限占空比、架空车轮 |
| 配电 | XT30 一分二 + DCP3512 | 电池并联分配到两块驱动；DCP3512只给逻辑系统降压，不串在电机动力回路中 |
| 定位 | 实验室 Vicon | 当前不可用，尚未做真实刚体、遮挡和延迟验证 |

电池、两块驱动、STM32、ESP32 必须共地。电机驱动动力线与逻辑降压支路应从配电点分开；
正式装车前增加总开关、可触及的急停/断电手段和适合线束的保险保护。

## 3. 软件现状

### ROS 2 / Linux PC

已经具备：

- Vicon 刚体位姿到 `map -> base_link` 的桥接、跳变拒绝和有效性状态；
- 目标位姿控制器、速度/加速度限制和 ROS 侧安全看门狗；
- RViz2 小车、目标点、计划轨迹和实际轨迹显示；
- 圆形、矩形、8字形航点轨迹发生器；
- 无硬件软件在环仿真；
- MC-Link v1 的 Python 编解码、CRC32、COBS和测试向量。

截至本次整理，ROS/Python 离线测试为 `25 passed`。

尚缺：

- ROS 2 到 ESP32 的正式 UDP 节点；
- `/car/cmd_vel` 到 `CMD_VEL`、`/car/enable` 到 `CONTROL_ENABLE`、急停到 `ESTOP` 的映射；
- `WHEEL_TELEMETRY` 和 `LINK_STATUS` 到 ROS 话题/诊断的映射；
- 会话重连、丢包统计、真实网络延迟记录和 rosbag 验证。

### ESP32-S3

已经具备：

- Wi-Fi STA、UDP 46000/46001 和 UART1 921600 8N1；
- MC-Link 帧头、CRC、会话和序号检查；
- UDP 超时后向 STM32 注入一次零速并锁住过期会话；
- `GPIO17/TX`、`GPIO18/RX` 的 UART 配置；
- 上电向 STM32 发送 `HELLO` 并等待 `HELLO_ACK` 的自动测试；
- 实板烧录、原生 USB 日志、Wi-Fi入网及早期UDP回环验证。

当前日志显示 `UART link self-test WAITING`，原因是两块开发板尚未接三线 UART。这不是固件故障。

### STM32F407

目前有三个相互独立的镜像：

1. `mecanum_f407_link_test`：921600 二进制 MC-Link，只做 HELLO/ACK，不初始化电机定时器；
2. `mecanum_f407`：115200 文本命令，只控制 Motor_A，带心跳、急停、20%占空比限制和编码器读取。
3. `mecanum_f407_motor_link`：921600二进制MC-Link，单电机状态机、速度PI和10 Hz遥测；未标定时锁止输出。

链路测试镜像已通过 DFU 写入并验证；单电机镜像只完成编译和主机测试，尚未烧录到真实电机系统。
主机侧文本命令解析和 MC-Link 测试均通过。

单电机A的`mecanum_f407_motor_link`现已接入二进制MC-Link、安全状态机、编码器PI和遥测，
并以“编码器每圈计数为0”锁住运动输出。下一步是无电池通信验证和实测编码器标定；四轮逆运动学、四路编码器
和四轮速度 PID 合并到同一个工程中。

## 4. 当前最重要的接口缺口

```text
/car/cmd_vel
     |
     +  ROS 2 UDP桥接节点已实现并通过HELLO在线测试
     |
ESP32-S3（固件已具备）
     |
     +  三线UART已完成HELLO/ACK全链路验证
     |
STM32链路测试（已烧录并验证）

STM32单电机motor_link（已烧录并完成无电池锁止验证）
     |
     X  编码器每圈计数尚未实测，因此保持高阻锁止

STM32正式四轮控制（尚未实现）
```

因此目前不应直接进入 Vicon 自动轨迹或四电机落地运行。先把每一层变成可独立验收的模块，出现
错误时才能判断是网络、协议、UART、电机方向、编码器还是 Vicon 坐标问题。

## 5. 推荐实施顺序与验收门槛

### 阶段 A：打通无电机通信链路（当前推荐）

1. 只连接三根线：ESP32 GPIO17 -> STM32 PD6、ESP32 GPIO18 <- STM32 PD5、GND共地；
2. STM32设置正常启动，复位两块板；
3. ESP32 USB日志出现 `UART link self-test PASS`；
4. 实现 ROS 2 `mc_link_bridge` 节点；
5. 验证 PC -> ESP -> STM -> ESP -> PC 的 HELLO、断线、CRC错误和重连。

验收标准：连续测试无错误；拔掉任一链路后进入安全状态；恢复时必须建立新会话，不自动恢复旧速度。

### 阶段 B：单电机与编码器台架测试

1. 只接一块驱动的 Motor_A，车轮架空；
2. 示波器/逻辑分析仪先确认 AIN1/AIN2 的 10 kHz PWM、零输出和死区；
3. 从 5%-10%占空比开始，确认正反转、霍尔A/B相和计数符号；
4. 测量每轮输出轴一圈的实际计数；
5. 做阶跃测试，建立单轮速度 PID 的初值和安全上限。

验收标准：急停、心跳超时和拔串口都能立即归零；正转计数符号统一；低速不失控；驱动和电机不过热。

### 阶段 C：四轮底盘与正式 STM32 固件

1. 固定 FL、FR、RL、RR 轮序和电机/编码器极性；
2. 扩展四路 PWM、四路正交编码器和四轮 PID；
3. 实现麦轮逆运动学，把 `vx/vy/wz` 转成四轮目标转速；
4. 输出 `WHEEL_TELEMETRY`；
5. 架空验证前进、横移、旋转，再进行低速落地测试。

验收标准：三种基本运动方向正确；零速无爬行；四轮速度跟踪可重复；任何通信超时都在STM32本地停车。

### 阶段 D：Vicon 外环闭环

1. 在 Tracker 中建立刚体并确认刚体中心而不是单个 marker 坐标；
2. 标定 Vicon 刚体原点到 `base_link` 的平移和偏航偏置；
3. 测试频率、遮挡、跳变、重连和端到端延迟；
4. 先做静态目标点，再做直线，最后做圆形/矩形/8字轨迹；
5. 用 rosbag 记录目标、实际位姿、命令、轮速、链路状态和 Vicon 帧号。

验收标准：遮挡或位姿超时自动停车；实际轨迹可重复；能够量化位置误差、偏航误差和恢复时间。

## 6. 可形成的四个项目成果方向

1. **Vicon闭环轨迹跟踪基准平台**：比较开环、编码器内环和Vicon外环的轨迹误差，最能直接体现Vicon的全局高精度优势。
2. **扰动与打滑恢复实验**：横向推动车体或改变地面摩擦，展示Vicon外环如何消除麦轮打滑造成的累计误差。
3. **轮式里程计/Vicon融合与遮挡恢复**：短时遮挡使用轮速里程计预测，Vicon恢复后平滑校正，适合作为算法型课题。
4. **K230D视觉任务 + Vicon真值评估**：K230D识别目标或标志，Vicon提供小车真值轨迹，用于评价视觉导航误差；应放在底盘闭环稳定之后。

建议先走方向1，并以方向2作为演示亮点。方向3需要更多状态估计工作，方向4涉及相机标定和坐标外参，适合作为后续扩展。
