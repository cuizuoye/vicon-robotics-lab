# 无电池 MC-Link 安全命令在线验证（2026-09-30）

## 边界

- ESP32-S3 与 STM32F407 通过 921600 8N1 UART 连接；两块板各自 USB 供电。
- PC 和 ESP32 使用手机热点，ROS UDP socket 只绑定物理接口 `wlp114s0`。
- 没有连接电池和电机；没有修改代理、虚拟网卡或系统路由。
- STM32 的编码器每轮计数保持 `0`（未标定），因此任何运动使能都必须被拒绝。

## 在线结果

| 操作 | `fault_bits` | `state_flags` | 解释 |
|---|---:|---:|---|
| 启动基线 | `0x08` | `0x09` | 未标定；会话有效且输出高阻 |
| `/car/estop=true` | `0x0E` | `0x09` | 未标定 + ESTOP 锁存 + UART 溢出；仍为高阻 |
| `/car/clear_faults=true` | `0x08` | `0x09` | 可恢复故障被清除，未标定故障保留 |
| `/car/control_enable=true` | `0x0A` | `0x09` | 使能未绕过未标定门槛；突发流量再次造成 UART 溢出 |

显式使能后的四轮遥测均为 `0.0 rpm`。测试结束前再次清故障，最终故障位恢复
`0x08`，ROS UDP 桥已停止。

## 本次发现与处理

手机热点出现明显的 UDP 突发/乱序。ESP32 的 200 ms UDP 看门狗锁住旧会话后，
UART 遥测仍可返回，原 ROS 桥会误判为“仍连接”。现已增加两层恢复逻辑：

1. 用 STM32 遥测中的 `last_command_sequence` 检测“遥测存在但命令序号不推进”；
2. ESTOP、清故障、授权等安全命令先换新 session，随后以新序号重复五次，并在此期间
   暂停周期速度帧。

这使急停与清故障能穿过当前不稳定链路，但 UART 溢出表明普通 50 Hz 控制链路还不
具备接电机条件。接电机前应在保持 STM32 150 ms 独立停机边界的前提下，测量 UDP
间隔分布，调整 ESP 会话看门狗/接收缓存和 UART 突发节流，并复测零溢出运行。
