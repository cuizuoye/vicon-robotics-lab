# 已选档6的600秒软件入口与实机准入

本候选响应用户选择：档6演示正常、2.00m/s²已足够，不再提高加速度，只把最大活动时间从60秒延长至600秒。原60秒快照和启动脚本保留，不覆写、不刷固件、不改ESP32/Tenda或电脑联网。

## 运动参数不变

平移≤0.70m/s、加速度≤2.00m/s²；旋转≤2.00rad/s、角加速度≤12.00rad/s²。每轮目标≤400RPM、PWM≤80%，平移与旋转共用原轮速约束。保持原始Sign的1:1水平位移＋相对旋转，Z不映射，无绿色参考目标、无固定电子围栏；Vicon不是避障系统。

最大活动时间为600秒，监督器、末级门和主机截止相互独立；原MCU630秒绝对运行预算和600ms链路看门狗不改。会话等待与清理预算扩大到840秒，不再被旧的240秒外层进程寿命提前结束。单击空格开始，再次空格/Esc/停止按钮停车，松键不停车。正常计时完成与人工提前停止分别保留原始原因，不把故障伪装成完成。

浏览器/输入100ms、命令100ms、定位200ms、反馈300ms、租约150ms，以及姿态/抬起、堵转、反向/换向、来源、签名和停稳确认等原保护均不变；数据恢复不会自动续跑。真实域129，软件域196，命令签名范围与60秒入口不同，实际端口继续全局独占。

## 当前可执行的命令

```bash
bash /home/PRIMARY_USER/vicon_mecanum_ws/tools/start_car_4wsc_stage6_600s.sh --check
```

默认或 `--check` 只核对文件，不初始化ROS、不打开硬件。软件回环排练使用同一脚本的 `--rehearsal --no-open`，仅允许专用127.0.0.1端口和合成Sign；软件代理的任何速度、停车和温升结果都不是实测。

**现阶段不安排600秒实车启动。** `--launch --site-ready` 仍要求实测审核文件，缺少时在ROS、硬件socket及网页构建前拒绝。新的同档60秒验收和“希望600秒”只作为变更依据，不自动生成测量、不设置物理合格状态，也不会把手动场地声明当作电流/温升审核。

## 实机开放前缺的记录

1. 在运动中主动停车的观察、该档速度/转速下的停车包络，以及包含底层600ms失联回退和车体外廓的余量审核。此前两次档4/档6试验都在计时结束时停止，毫米级剩余位移不是满速制动距离。
2. 同一硬件配置的真实电流、驱动板/电机温度及受控600秒试验适用性审核。只有普通万用表且未测到的项目继续未知，不以“硬件正常”代替数值，不伪造热测量。
3. 当前所有预期路线的实际最小空旷余量。全域跟踪模式不应继续把历史参考围栏的0.50m当作全场地硬上限；准入要求实测完整停车包络加原0.20m额外余量不超过明确审核的实际净空。缺少数值仍不开放。

量纲校核保留：仅0.70m/s×0.60s的最坏看门狗等待就有0.42m，再加190×210mm车体半对角线约0.142m，尚未计入实际制动，不能用1～2mm的静止末段观测冒充完整包络。这里只说明审核边界，不自行安排人为断链或高速失联试验。

未批准的模板随交付保留，所有物理/审核标志默认false、测量null，不能直接改名或仅把false改true来开放。真实记录的路径和SHA会在准入时核对，必须是本版4WSC、同档6的物理数据，软件与旧固件数据不能替代。有效审核后仍要新的现场声明、自检及操作者一次空格才开始；不会自动启动或自动升档。

## 软件证据边界

完整600秒测试采用实际ROS、签名末级门、独占UDP软件桥和原版native C固件代理，浏览器协议对等端验证倒计时/输入与断连；不是实际浏览器渲染长测、真实无线链路或物理600秒验收。

离线代理修正了一个补算时间步的因果错误：新收包必须等到不早于其接收时间的控制步才处理，包括不足1ms的接收小数部分。这只改软件代理，不改C固件或实际桥接层，也不放宽任何时钟容差/反馈截止。原始失败草稿和日志均保留。
