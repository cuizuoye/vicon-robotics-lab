# 浏览器SIM12迁移与续测

## 当前入口

```bash
bash /home/PRIMARY_USER/vicon_mecanum_ws/tools/start_car_browser_local.sh
```

等价专用命令：`bash /home/PRIMARY_USER/vicon_mecanum_ws/tools/start_sign_browser_sim_1p2.sh`。当前默认已从只读动画升级为**真实Sign→数学软件车**，不是实车入口；旧只读动画使用`--readonly`。原Tk入口和矩形程序保持原样，但本轮不再使用Tk窗口。

正式软件候选：`prepared_v4/`，校验入口为`--check`。`RELEASE.json`记录软件回归资格、36份证据文件SHA、源码及产物清单；实车资格、真人真实Sign完整验收、原桌面卡死根因解决标志仍为false。

启动会重新确认真实Sign新帧和固定几何定义，在失能零速下完成冷启动及0.75秒稳定基准，再开放网页。READY后轻按松开空格启动；再次空格、Esc或停止按钮结束。松键不停；网页须在前台，故障后不自动恢复。入口持有单会话锁，重复启动不能接管旧会话。

## 迁移边界

复用原SIM12未修改的控制算法、独立监督器、末级门、源绑定、专用签名和一阶数学执行器。私有DDS191及随机命名空间，无电机桥、ESP32连接或固件写入；car01仅只读观察，不作为软件车反馈。

保持1:1平移/相对旋转、Z不映射、无固定电子围栏；直行上限1.20m/s、45°斜向合速度约0.849m/s、平移加速度4.00m/s²，角速度2rad/s、角加速度12rad/s²，最长600秒。平移与旋转共享轮速余量，不保证同时各自满速。

替换的是显示与按键输入层：使用本机浏览器Canvas，不构造Tk窗口或X11键盘查询对象；控制与画面分流，画面只保留一个待发送的最新槽。画面数据约50Hz更新、绘图最多约30Hz、像素比限制为1；字体加载完成后才连接输入。未降低100ms界面/挑战保护、150ms租约、200ms定位或300ms执行器反馈保护，也没有通过后台定时器代替网页主线程存活。

## 同步性观察，不能混同为全部达标

6m×5m合成手势的最终协议长流程中，旋转误差P95约6.59°、最大11.12°，静止保持段P95约1.69°，拟合旋转跟随滞后约50ms，符合既有临时旋转演示指标。这只是数学模型下的拟合，不是完整物理端到端延迟。

同一混合平移/旋转手势的XY间距P95约0.524m、最大0.789m，仍明显存在落后；不能把“功能与安全回归通过”说成“大幅快手势完全同步”。位移同步性尚待真人Sign采样和后续分析。当前测试手势峰值约1m/s，混合斜向及旋转占用轮速预算；未将其当作纯直行1.20m/s稳态验收。数学执行器时间常数0.12秒，未辨识电流、摩擦、热或实际电机动力学，不能据此推断硬件能力。

## 未隐去的失败与修复

1. 初版真实ROS冷启动中出现约343ms间断，100ms保护在未使能时终止；现将冷启动和零输出稳定检查放在开放网页之前，没有放宽活动保护。
2. 首轮实际浏览器出现CLIENT_VIEW_STALE_100MS，且尚未使能；现提高小报文更新频率、保留有界队列，字体就绪后才连接，实际串行60秒复测通过。
3. 一轮网页ACTIVE约51秒时触发CONTROL_TIMER_GAP。网页主线程最大间隔仍约29ms，后台控制与位姿消费发生间断；时间与另一组ROS节点冷启动重合，但没有证明具体根因。后续不再并行启动ROS回归与人工演示，并给正常入口加单会话锁；未改控制超时阈值。独占串行60秒通过不等于排除所有长期调度风险。
4. Esc初测发现页面曾保留旧ACTIVE文本。末级门已归零并确认停稳，但显示滞后；现仅依据后台停止证据更新最终状态，未确认停稳时显示STOP_UNCONFIRMED。

上述失败原始目录均保留，不计为通过，也没有通过改写旧原始记录隐藏。
