# 虚拟杆安全操作台验收（2026-10-22）

## 目的与边界

Sign标定杆充电、Vicon无法跟踪时，优先补齐可继续离线开发的操作端。此版使用鼠标虚拟杆、持续空格使能、真实ROS软件监督器/末级门/软件车，不需要杆、电池、Vicon或实车连接。

固定ROS域96、LOCALHOST、`/wand_safe_sim`命名空间。虚拟位姿不发布为域0的真实Sign；没有ESP32/STM32通信节点或硬件控制入口。未修改网络设置、未刷固件、未启动实车。已有域0/99程序未被本轮启停。

## 完成内容

- `operator_model.py`：新鲜反馈、持续按键边沿、早按与重复抑制、失焦/界面卡顿锁止、重新准备和虚拟输入范围。
- `operator_console.py`：中文原生Tk界面，蓝车/橙目标、虚拟杆、准备/暂停/停止/故障确认/仿真急停；界面驱动租约，界面卡住不会由后台线程代续使能。
- `wand_safe_console.launch.py`：仅包含已有独立安全仿真后端和一个虚拟操作端；操作台退出时只关闭本次launch。
- 安全监督器状态增加双时基和当前锚点字段，供界面校验与重新对齐；没有改变原矩形控制器或安全控制算法。
- `tools/wand_console_ui_smoke.py`：在临时Xephyr独立显示器内向本程序Tk控件注入事件；不操作用户桌面键鼠，结束后清理自身显示器/软件节点。
- 已有python3-tk、Pillow、Xephyr满足当前测试条件；未安装软件或改动系统网络。

## 操作

```bash
cd /home/PRIMARY_USER/vicon_mecanum_ws
source /opt/ros/jazzy/setup.bash
source install/setup.bash
ros2 launch mecanum_wand_control wand_safe_console.launch.py
```

按顶部提示轻按并松开一次空格以确认松键 → 点击准备 → 等待“准备就绪” → 持续按住空格并拖动虚拟杆。松开、切出窗口、暂停、停止都会释放使能；返回窗口不自动恢复。恢复前等待PAUSED/停车确认、按提示完成松键解锁，再重新准备。故障需先解除原因、释放空格、等待停车反馈并确认；仿真急停需退出重启。

2倍相对位移、固定起步车头方向、0.05m/s合速度和0.08m/s²加速度沿用安全配置。虚拟杆半径0.245m，会话内同时约束距当前捕获点的输入；30秒会话限时仍有效。每次重新启用捕获当前原点。回中不是停车键，仿真急停不是硬件急停。

## 仍未验证

本轮不是人手实体键盘的现场验收，不是无线/电机/轮地/硬急停测试。真实Sign到新安全链路的适配仍未接入；杆充电结束后需先做真实输入驱动软件车的联调，实车迁移仍须单独确认。

不用杆仍可继续的独立工作：加入录制轨迹回放及统计报告、长时重复启停/随机故障压力测试、迁移参数与验收清单。不要将仿真安全配置直接当成真实场地或硬件标定。

## 用户反馈后的输入流程修复

用户报告准备并按空格拖动后不动。本轮检查时该窗口已关闭，已有launch日志只记录正常启动和退出，没有当时的按键状态，不能将推测当成那一次操作的确切原因。

在原模型中明确复现：启动/失焦后`blocked=True`且`key_down=False`，`can_start`却返回True；准备成功进入ARMED后，第一次按空格被本地锁止拒绝。原测试在准备前主动发送松键事件，掩盖了这条路径。另一个提示缺陷是过早按空格时要求再次准备，但ARMED下准备按钮已禁用。

修复不绕过松键保护：锁止时准备按钮不可用；顶部持续显示输入解锁、等待握手、准备就绪和停车步骤。提前按键后提示松开再按住，不要求重复准备。增加`UI_STATE`变化日志。更新GUI回归，在未预发任何松键事件前切换窗口焦点，并使用ttk鼠标按下/释放绑定点击准备，而不是直接调用`.invoke()`。

实车与旧矩形入口仍不在本次修改范围内。注意操作是持续按住空格，不是点按后再单独拖动。

修复后最终记录：`docs/wand_console_2026-10-22_input_fix_final/summary.json`。GUI十项检查通过，真实ROS软件车有位置变化，最后PAUSED且停车确认；428项回归通过（275+153），构建通过。该轮释放空格至末级零输出约0.062秒，失焦约0.069秒，前后域0七个运动/使能话题发布者均为0。原控制包72文件仍与既有清单一致。

## 真实Sign回归：长按、Z轴及围栏提示修正

真实杆充电后，`wand_sign_acceptance_2026-10-22_charged_preflight.json` 的5秒只读采样收到Sign 1642帧、car01 1625帧，无重复源/旧运动入口冲突。所有后续操作均为domain94 `mode=shadow`，没有构造硬件桥，没有刷写或实车运动输出。

现场遇到的问题分别记录，不能把保护停车统一称为按键问题：

- 首轮ARMED阶段安全门回调间隔约175ms，触发100ms硬保护。关闭仍残留的旧只读预览/旧仿真后重启本轮软件；未放宽控制间隔。该轮不计通过。
- 原5ms延迟的X11 Release/Press去重无法覆盖实际排队延迟。真实输入操作台改用独立只读X11键盘位图核实持续按下，同时在GUI周期检查丢失松键。轮询只能撤销，不能产生使能边沿；失焦、租约、100ms调度、硬故障锁存保持原样。不更改桌面自动重复设置，原虚拟事件入口不变。
- 修正后的现场会话持续ACTIVE约5.8秒后，由`GOAL_OUTSIDE_FIXED_ARENA`停车。原点Sign z约0.035m；越界前z约0.353m，同时水平dx=-0.0394m、dy=+0.1803m。杆Z没有映射，水平目标约dx=-0.0788m、dy=+0.3606m，超出该保守足迹/余量配置的固定围栏。之后操作台记录了用户ESTOP并正常关闭；不能自动清除锁存。
- 原界面“杆位移≤0.25m”不符合本现场配置；改为根据起点、朝向、足迹和余量计算的全方向水平安全半径（中心约0.140m），建议步长不超过0.10m。显示Z/ΔZ且明确“不映射”、绿色车中心可用区、中文故障原因以及松键→确认可恢复故障→准备的顺序。原点实际在持续使能边沿捕获，界面不再在ARMED阶段显示旧会话位移。
