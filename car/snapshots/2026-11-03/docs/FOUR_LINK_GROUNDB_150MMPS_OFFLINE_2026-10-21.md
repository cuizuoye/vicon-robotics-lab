# 4WGB 0.15 m/s Vicon恢复演示档

## 目标

当前4WGA把车体x/y速度限制为0.10 m/s。直接改电脑端参数不会变快；直接退回4WG9虽然可到
0.20 m/s，却会把STM32命令租约从600 ms降回150 ms，与已经测得的160--555 ms无线接收
空档冲突。因此新增独立固件身份`4WGB`，不覆盖或冒充4WGA。

## 唯一扩大项

- 车体x/y单轴命令上限：0.10 -> 0.15 m/s。
- 状态身份：`4WGB`，数值`0x42475734`。

以下边界不变：轮缘速度0.20 m/s、目标1200 cps、35% PWM上限、30%受限启动、600 ms命令
租约、150 s单圈截止、500 ms静止后安全重装填，以及真实故障不可由重装填命令清除。
0.15 m/s下，完全失联时600 ms租约内的理论最大陈旧直线行程为0.09 m，之后STM32独立
关闭输出。

主机连续矩形入口同时从每边两个路径点改为只保留四个角点，去掉边中点的停车；四个角仍
各驻留0.80 s，以降低齿隙/惯性造成的换向反馈毛刺。3 m x 2 m矩形理想匀速时间由约100 s
降到66.7 s，实际还包含减速、角点驻留和圈间重装填，预计约75--90 s。

## 离线验证

- 流式固件原生ASan/UBSan：悬空档、4WG1至4WG9、4WGA、4WGB共12种配置全部通过。
- ROS/Python：274项通过。
- ROS包构建：通过。
- STM32 Debug ARM交叉编译：通过，FLASH 42312 B，RAM 7448 B。
- 同一新构建树重建4WGA的BIN与已接受版本逐字节一致，SHA-256仍为
  `e40ad03060fa1c7b73e52513bcaa182a2c678d5d823f39faa00e98eb032204e8`。
- BIN：`stm32/mecanum_f407/build/GroundMotionB_20261021/mecanum_f407_four_link_groundb.bin`
- SHA-256：`9d539903fbd621578abc941dec559d27de54642e106cbcbffcd81e26f5af647a`

## 烧录状态与硬件边界

用户确认动力断开并连接ST-Link后，目标识别为device ID `0x413`、1 MiB Flash、3.19 V。
两份完整Flash备份逐字节一致，SHA-256为
`d8a5c0af5866bc329ec4e69ba35740dd7c1600674624f2d18505a3e69dca548e`；其前42312字节
与已接受4WGA镜像精确一致。

首次HOTPLUG写入在Flash加载器初始化阶段失败；独立读回确认旧4WGA仍完整，没有发生部分
擦除或写入。随后使用这块板已有成功记录的硬件复位连接模式完成4WGB烧录和工具校验，独立
读回与构建BIN逐字节一致，SHA-256均为
`9d539903fbd621578abc941dec559d27de54642e106cbcbffcd81e26f5af647a`。最终Cortex-M4保持
停核、动力断开，没有发送电机命令。完整备份和原始日志位于
`stm32/mecanum_f407/backups/pre_4wgb_20261021_ulokcn/`。

恢复Tenda并重新上电后，运行时精确身份`4WGB`、故障0、`permitted=0`、四轮反馈/目标/
PWM/比较寄存器全零均已确认。随后一次性3秒落地直线测试通过：轨迹有效3.053 s，命令和
STM32车体目标均达到0.15 m/s；Vicon净位移0.3863 m，全程458个有效样本、0个无效样本，
故障始终为0，最大原始占空比120 permille。截止后运动门关闭，四轮目标、反馈及输出归零。
录包位于`bags/4wgb_150mmps_direction_probe_20261021/`。

连续矩形控制栈已重新启动在`STANDBY`，仍需把小车移回合适起点后验证一整圈和随机干扰。
