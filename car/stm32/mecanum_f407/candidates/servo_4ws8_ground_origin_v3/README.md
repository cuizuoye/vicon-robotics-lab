# 4WS8 短程落地入口：使能时原点同步修复（V3）

本版本只修复电脑端监督器及短程门控。沿用已读回核验的 4WS8 固件，
不刷 STM32、不修改 ESP32/Tenda、不更改原矩形入口，也不启动实车。

## 原点和计时语义

- 准备/ARMED：只绑定本次 arm epoch、累计真实停稳及执行原有健康检查。
  可以在保持松键的情况下拿起、调整 Sign；不捕获短程原点、不消耗单次
  测试预算、不累计车程，5 秒计时尚未开始。原有姿态突跳保护仍然生效。
- 新的按住使能边沿：原控制器先要求定位、停稳、门控和操作员租约有效，
  再建立 1:1 映射。监督器短程保护直接复用该映射的车/杆原点及使能时间。
- 末级门：必须先收到 ARMED，再收到有效且零指令的首个 ACTIVE 帧。
  共享该帧的车参考点和开始时间，并独立使用自己的新鲜 Sign 数据建立
  杆保护基准；不直接信任任意外部杆原点。丢失首个零速帧时保持零输出、
  撤销签名许可，不从后续非零运动帧补抓原点。
- 运行中不重新抓原点，不因新帧、恢复定位、松键、确认或再次准备而
  重置已消费的时限/行程。一个进程只允许一次使能观察。

两个进程的原始订阅采样可能存在接收时差，因此末级门保留独立输入检查，
而不是把监督器的杆坐标未经验证地复制进保护器。

## 保持不变的约束

- 固定档 4：速度上限 0.70 m/s，正常指令加速度上限 0.80 m/s²。
- Sign 水平位移 1:1；Z 和杆姿态不映射为小车运动。
- 保存的 3m×3m 活动区、四边 50cm 缓冲、车体外形和额外安全余量不变。
- 单次最多 5 秒；杆/目标偏移 15cm、车中心偏移 20cm、路径 25cm 上限不变。
- 使能前的软边界检查、松键/失焦、遮挡、反馈丢失、来源/签名、时钟、
  越界、速度/加速度、抬车/倾斜、硬件故障锁止及 MCU 看门狗均保留。

这是单次小位移观察入口，不是 0.70 m/s 连续地面运行合格证。
没有新增停车距离、电流或温升测量，也没有进行任何物理落地试验。

## 离线验证

`prepare_host.py` 只复制到独立输出目录、生成本版本文件、执行离线测试、
构建两个独立前缀的 ROS Python 包并复核受保护输入哈希。它不会调用
固件写入工具、Vicon SDK、`rclpy.init()`、ROS launch 或实车 UDP 接口。
Tk 检查使用隐藏窗口和假节点，不发送服务请求。

回归覆盖：准备后拿起/多次调整/等候超过 5 秒再使能、首次使能零输出、
后续 5cm 的 1:1 跟随、Z/姿态不映射、使能后 15cm 和 5 秒保护、缺失
零速首帧、禁止重抓原点、旧故障保护、实际节点报文编解码与 HMAC 输出。
还用 10 月 23 日已保存的原始杆位姿记录，分别复现旧版误停和验证新版。

准备结果位于：
`docs/wand_servo_4ws8_2026-10-26/ground_origin_sync_v3/ready/`。
其中 `RECORDED_FLOW_REPLAY.json` 是离线回放，不是实车验收记录。

## 只读入口检查

```bash
cd /home/PRIMARY_USER/vicon_mecanum_ws
source /opt/ros/jazzy/setup.bash
source install/setup.bash
source docs/wand_servo_4ws8_2026-10-26/ground_origin_sync_v3/ready/runtime/install/local_setup.bash
python3 docs/wand_servo_4ws8_2026-10-26/ground_origin_sync_v3/ready/launch_pilot.py --manifest docs/wand_servo_4ws8_2026-10-26/ground_origin_sync_v3/ready/build_manifest.json
```

上面的默认操作仅核对文件，不打开设备、定位或控制链路。
只有再次确认当前场地、定位、朝向和立即断电条件后，才另行安排
0.70 m/s、0.80 m/s²、杆前移约 5cm 的单次 5 秒落地观察。
