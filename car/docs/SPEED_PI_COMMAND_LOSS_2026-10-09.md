# 单轮通信断流停机验收与四轮参数复用

历史报告提示：本文件保留2026-10-09试验状态。2026-10-10已在断动力状态集成并烧录独立`forward_pi_v1`，完成读回一致及无动力检查；下文旧固件状态/工具入口不适用于当前板内程序。后续见[四轮前进速度环集成记录](FOUR_FORWARD_PI_INTEGRATION_2026-10-10.md)。

日期：2026-10-09。当前板内仍是`speed_pi_v2`、115200文本协议；本轮未重新烧录，未改接线、热点、代理或虚拟网卡。现场已确认只有左前轮向前、自行停轮、动力已拔掉，STM32保持独立供电。

## 本次实机结果

只发送一次`run FL 300 S5`，最大输出10%，其余三轮保持零指令。主机维持心跳约1.8秒，然后停止发送所有命令：不是先发stop再声称固件自行停机。

- 18帧运行遥测，首末相隔1700ms；采样/测速100Hz，周期最小/最大10/10ms。
- 34次心跳全部收到ACK；断流后的独立观察阶段没有发送心跳、status或stop。
- 首次故障帧MCU时标62990ms：`fault=0x4`（命令/心跳超时）、`en=0`、`sel=0`、`used=1`，四路目标/PI输出与8个实际CCR全部为0。
- 此后7帧保持同一故障锁存；尾部5帧计数稳定、四路速度为0，非选中轮在本次连续观察期间计数未变化。完成这些证据后才由主机补发stop/status。
- 固件设定超时150ms；主机从最后一次心跳写出到收到故障遥测约0.294秒。该时间包含串口队列、传输和10Hz遥测等待，**不是MCU精确超时或轮子机械停转时间测量**。
- 操作者确认：仅左前轮朝前并自行停止，其余静止，已断动力。
- 断动力后只发stop/status再观察约5秒：采样100Hz，`fault=4`、`used=1`持续保持，八路CCR为0、四轮计数和速度稳定。最终MCU时标307840ms。

断动力后的计数为FL273/FR4/RL1/RR−3，与试验结束时FL270/FR1/RL−2/RR−3之间没有连续观测；不能把开关切换间的差值归因于受控运动，也不作为里程精度证据。

结论：当前单轮台架固件的UART心跳/目标断流自主归零、故障锁存以及现场停轮通过。未验证真实Wi-Fi/UDP断网、IWDG故障注入、机械制动延迟或四轮落地控制。

## 加快推进：复用初始参数，不复写标定

按用户要求跳过其它三轮的重复逐轮PI整定。四轮共用初始`Kp=0.1千分比/cps`、`Ki=0.5千分比/计数`；这些增益不是已经充分整定的最终值。

各轮CPR与方向继续分别保留：FL1059.67、FR1049、RL1055.67、RR1061；电机/编码器前进符号为`+1/−1/+1/−1`。共用增益不等于共用计数，也不等于四轮实机性能均已验收。保留所有原始测量，不增加逐轮重复测量。

## 四轮联动软件准备（离线，未烧录）

新增独立HAL-free模块`four_forward_group.h/.c`，不修改现有单轮算法与已验证镜像，也未加入任何固件目标。只为下一次悬空整体联动准备，不是正式ROS2/MC-Link或轨迹控制入口。

- 固定四轮前进轮缘目标50mm/s；按各自CPR与标称60mm轮径换算为约278–281cps，不简单让四轮都取同一cps。
- 每轮复用既有单轮PI算法并独立保存反馈、积分、斜坡和进展时限；四个真实编码器通道各送入自己的环。单轮库适配数组不是遥测证据，后续遥测需独立读取真实硬件计数。
- 任意环出现方向/超速/无计数/通信超时/采样时序故障，全组清积分、目标与输出；四环全部通过才发布本次新PWM。后续HAL必须在固定时钟、受保护上下文中一次应用全组结果，不能逐环直接写PWM。
- 保留最大10%输出、100Hz、命令150ms、运行5秒上限；启动前连续静止500ms、采样新鲜、心跳新鲜，每次初始化仅一次运行。stop不清故障或恢复额度。
- 初始化仅用于动力断开时的启动/复位流程，禁止把重新初始化当成在线清故障接口。

验证：新增9组离线C测试通过（含ASan/UBSan），覆盖四轮方向与CPR、独立反馈、任意轮故障全停、两类无进展、断流锁存、5秒时限、静止/新鲜度、单次额度和计数/时钟回绕；既有9组单轮速度算法回归通过。主机186项离线回归通过。新增模块STM32F407目标文件交叉编译通过；尚未集成为可烧录四轮联动镜像，四环实际ISR耗时及联动性能未验证。
