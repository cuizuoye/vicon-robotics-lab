# 4WG9 无需重新上电的安全运行额度重装填（实车短测通过）

## 问题与根因

4WG8 的首次 1 m Vicon 直线运行已经成功，但同一次上电后的第二次运行在车轮动作前被
STM32 以 `0x00020000` 拒绝。该位是 `FOUR_LINK_REJECTED`，不是电机、编码器或无线
断流故障。4WG8 的 `motion_started` 和 `run_used` 在一次正常运行结束后有意保持为真，
因此旧设计必须复位或重新上电才能恢复一次运行额度。

## 4WG9 的改动范围

新增独立固件身份 `4WG9`（`0x39475734`），保留 4WG8 的运动参数：

- 车体平移上限 `0.20 m/s`；
- 轮速目标上限 `1200 cps`；
- PWM 绝对上限 `35%`，启动补偿上限 `30%`；
- 命令租约 `150 ms`；
- 单次运动绝对时限 `150 s`。

4WG9 复用现有 MC-Link `CONTROL_ENABLE.clear_latched_faults` 位，但仅赋予它“健康状态下
重装填一次运行额度”的窄语义，不是通用清故障命令。STM32 只有同时满足以下条件才会清除
`motion_started`、`first_motion_ms` 和 `run_used`：

1. 运动门已关闭且四路输出为零；
2. STM32 和四轮控制组故障位均为零；
3. 新会话已经连续发送至少 `600 ms` 的失能零速基线；
4. 最近一条失能零速命令不超过 `100 ms`；
5. 编码器实测连续静止至少 `500 ms`，且反馈采样不超过 `30 ms`；
6. 四个 PI 控制器的目标、斜坡、积分和原始占空比全部为零。

急停、失联、运行超时、堵转、反馈、配置以及其它真实故障均不能通过这个命令清除；条件
不满足时仍锁存 `FOUR_LINK_REJECTED` 并保持零输出。重装填不会直接开运动门，随后仍需独立
的 `CONTROL_ENABLE`、ROS 安全门、新鲜 Vicon 位姿和新鲜速度命令。

主机侧只在精确识别到 `4WG9` 时执行上述流程。4WG7/4WG8 的原有启动行为保持不变，避免
旧固件把重装填位当作非法清故障请求。

## 离线验证

- 固件原生 ASan/UBSan：悬空版及 4WG1 至 4WG9 共 10 个配置全部通过。
- 4WG9 专项状态机：第一次运行、正常失能、500 ms 实测静止、新会话零速基线、安全
  重装填、第二次运行全部通过。
- 同一专项确认：注入 ESTOP 后，重装填命令不能清除真实故障，输出保持为零。
- ROS/Python 完整回归：`251 passed`。
- ROS 包：`colcon build --packages-select mecanum_vicon_control --symlink-install` 通过。
- 4WG8 使用原验收时的 Debug 配置重建，旧、新二进制 SHA-256 完全一致：
  `32b65461b26467dd2cfb78fcc257b6fe1eee35ac1bf1b3723de8380d0e894a54`。
- 4WG9 Debug 二进制 SHA-256：
  `086b6edb631c0035c382dd3f6e59dd5aa4048e3d40765a6ebefb4dcf132178b0`。
- 4WG9 ELF：text `42292`、data `12`、bss `7436`，总计 `49740` 字节。

## 烧录和实车验收

2026-10-21 用户确认动力电池关闭后连接 ST-Link。目标识别为 device ID `0x413`、1 MiB
Flash、3.20 V。冻结独立看门狗后两份完整 Flash 读回逐字节一致，SHA-256 为
`3ea992fcd43c4a1cffe94528c7c3f8afd92a2c073c25aa2b6c39cfa3d94b2604`；其前
41,900 字节与已接受 4WG8 镜像精确一致。

4WG9 随后完成单次烧录和工具校验，独立读回与构建 BIN 逐字节一致，SHA-256 均为
`086b6edb631c0035c382dd3f6e59dd5aa4048e3d40765a6ebefb4dcf132178b0`。最终保持
Cortex-M4 停核、动力断开，没有启动电机。完整记录及回滚镜像位于
`stm32/mecanum_f407/backups/pre_4wg9_20261021_mdpqj6/`。

恢复 Tenda 和动力后，在同一次上电中完成了两次受保护的 3 s 直线短测，测试速度上限
`0.05 m/s`，每次均由运行守卫在 3 s 到时后主动失能：

- 第一次从 `(0.631947845, -1.070011670)` 到
  `(0.643042274, -0.916984303)`，位移 `(0.011094429, 0.153027367) m`，
  合位移 `0.153429011 m`；
- 不重新上电直接进行第二次测试。运行守卫先确认 4WG9 安全重新布防，再重新使能；
  从 `(0.643465493, -0.913400758)` 到
  `(0.655372540, -0.762410428)`，位移 `(0.011907047, 0.150990330) m`，
  合位移 `0.151459095 m`；
- 第二次录包中 `/car/clear_faults` 只有一帧；结束后 `fault=0`、`permitted=0`，
  四轮目标、反馈、原始占空比和定时器比较值均为零；所有 ROS 节点随后正常退出；
- 两次位移方向和距离一致，确认当前安装下 `invert_body_xy=false`，并已把恢复直线硬件
  启动文件的默认值改为该实测结果。

对应录包为 `bags/4wg9_direction_probe1_20261021/` 和
`bags/4wg9_direction_probe2_rearm_20261021/`。这组测试确认了“同一次上电可安全重复运行”
以及方向映射，但不替代后续更长距离、额定 `0.20 m/s` 或人为扰动恢复的分阶段实车验收。
