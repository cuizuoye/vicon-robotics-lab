# 单击模式启动通信修复候选（离线）

只改独立上位机副本；旧单击、长按、矩形、固件和网络配置保持原样。
关闭了本聊天刚启动的未使能故障会话；没有停止共享 Vicon 接收器。

## 修复内容

- 时间基准使用同会话、同序号、正确应答标志的 MCU HELLO_ACK 与 PC 原始 HELLO 源时间。
  不把首帧遥测的接收时刻当作准确基准，不改写协议中的发送时间。
- 完整握手往返必须不超过40ms。它只是启动资格门，不是单向延迟的实测值。
  超限应答不交给原会话状态机；最多三次 HELLO 尝试，之后明确保持未就绪。
- 就绪前须有双路独立递增的真实轮速/184字节诊断，各至少五帧、源跨度至少400ms，
  且原始失能零输出、无故障和实测静止条件成立；选档和准备继续受原门控约束。
- 健康且从未准备的断链：先等待最后零速报文后的650ms，再使用新会话、清空旧缓存、
  重新确认时钟/零输出/选档。不得沿用旧选档计时器、旧准备原点或反馈时间戳。
- 一旦出现准备意图，时钟固定；断链后不自动 HELLO、补准备或恢复运动。
  MCU故障、CRC/身份错误、过期/重复/时钟跳变均不能用重新建基准掩盖或清除。
- 新提示明确显示等待握手/连续遥测建基准，而不是泛称唯一来源冲突。

原120秒、1:1映射、固定前[-1.5,0.5]/左[-0.4,0.5]米活动区及50cm缓冲不变。
原0.70m/s、0.80m/s²、200ms反馈期限、100ms命令期限、150ms操作租约不变。
原MCU 120ms延迟/60ms超前保护、600ms线端租约和150秒上限不变。

## 验证与边界

回归包括真实失败遥测时序回放，以及实际 Python 传输节点方法经纯内存假UDP连接
现有4WS8本地C控制器模型。测试禁止真实Internet套接字和rclpy.init；不启动ROS/Vicon
控制节点，不打开小车通信端口。真实遥测回放所用的合格ACK是显式合成输入，因为
原记录没有保存ACK原始负载；不能声称原硬件握手已满足新40ms门限。

合格往返握手/连续遥测、慢应答、旧会话、超时、CRC、真实底层故障、准备后断链、
完整准备/使能/零速/运动/停止等路径均需离线通过。原算法逐文件比较，原安全决策
另做AST比较；旧版本用哈希保全。

若实机往返持续超过40ms，本候选会拒绝就绪而不是放宽保护。不能保证仅改上位机
便消除所有无线抖动，也不能宣称电流、温升、停车距离或硬件可靠性已验收。
已有0x40000不会被此候选清除；后续实机试验仍需单独确认，不自动重开或运动。
