# 无级调速：独立浏览器软件实验，不覆盖固定基线

只在软件车运行。正式固定基线仍用 `tools/start_sign_browser_direct.sh`；本候选不改变固件、ESP32、Tenda或原矩形。
实验入口准备通过后：`bash /home/PRIMARY_USER/vicon_mecanum_ws/tools/start_sign_browser_adaptive.sh`。
保持实车断电/未连接。浏览器自动READY后单击空格开始，Esc/再次空格停止；最长600秒，松键不停车。

## 调速含义

这里“离得远”指橙色1:1目标与蓝车的追踪误差，不是手持杆的人和真实小车在场地中的物理间距。
手速前馈决定主要移动速度；位置误差决定追赶，远误差或快手势提高加速度预算，近距离/慢手势减小。转角误差与手的角速度采用同一结构。
平移预算连续在1～4m/s²之间，角加速度预算连续在1.5～12rad/s²之间；速度仍≤1.20m/s，角速度≤2rad/s，共享381.97RPM轮速预算。不是自动切换固件档位；固件档位只规定不可越过的安全上限。
接近目标但必须制动/反向时，允许预算升高，不能为了“近了就柔和”而削弱必要制动。失焦、Esc、失联和故障撤权不经过柔和斜坡。
仍只显示真实Sign的1:1目标，不恢复绿色中间点、电子围栏或代理点超前限制。

## 算法来源与边界

依据ArduPilot公开的平方根误差校正/速度前馈结构与Nav2加减速约束思想，独立实现数学公式和项目前馈调度；没有拷贝整套飞控代码，也不是声称成熟项目替本车完成了验证。
Ruckig官方说明普通逐点位置轨迹会落后移动信号，专用Tracking接口属于Pro；这里不引入它、不做云端轨迹规划、不在1:1目标之前再加一个轨迹生成器。
来源与公式、逐场景结果及未完成事项见 `docs/wand_adaptive_servo_2026-10-30/TECHNICAL_NOTE.md`。

固定基线的真实快速手势回放仍有轮速饱和。候选在可行速度的多项动作中改善，但极快混合手势约4%平面RMSE退步，故保持实验状态，不自动晋升为更优的真机版本。真实Sign的人手体验和所有实车指标尚未验证。
