## 修复内容

### 浏览器

原处理收到 `blur` 就结束，无论网页当时是否仍有焦点。新处理同时采集真实的 `document.hasFocus()`、可见性、顶层/子元素事件来源、`isTrusted`、活动元素标签、窗口尺寸及全屏状态。单凭事件名、不伴随失焦/隐藏的事件，不再结束演示。

真实失焦或页面隐藏仍立即撤权；原20ms周期检查、100ms主线程/画面/输入证据保护不变。没有防抖宽限、后台续命、自动恢复或合成空格。关闭页面、Esc、再次空格和停止按钮仍终止。若操作系统确实把焦点移到别的应用，仍会停车；本修复不能冒充已消除外部应用抢焦点。

新增 `/diagnostic` 只保存非权威焦点证据，不向ROS传递动作，不刷新nonce、输入证明或运动租约。日志要求同源、会话令牌、严格记录格式及单调诊断序号；请求体最多2048字节、每秒最多10条、每会话最多256条、待写缓冲受限。不记录令牌、窗口标题或任意网页内容；诊断失败不能授予权限。

### STM32接收逻辑

保留CRC、同会话及新序号校验之后，区分明确撤权与申请/续持运动权限：

- `CONTROL_ENABLE(enabled=0, clear=0, reserved=0)` 无论时间是否陈旧都只能停机；不清已有故障、不选择档位、不重新布防、不刷新命令租约或建立零速准备证明。只有时间有效时才推进源时间顺序屏障。
- 不带ENABLED、且三轴全零的过期 `CMD_VEL` 只撤权，不因该停车帧新增源时效故障，不刷新命令时效、进度、准备基准或时间锚。
- 带ENABLED的零速帧仍是运动租约，不能走上述分支；非零报文、选档、使能、清故障/健康预算重置继续受原120ms落后、60ms超前及时间回退保护。
- 已有急停、反馈/时序、指令过期、持续运行预算等故障不被撤权帧清除；600ms看门狗仍先于报文处理执行。旧序号、外来会话不能借该分支改变当前会话。

代码只修改独立固件中的接收判定，未修改速度规划、PI控制、加速/换向逻辑、档位表或电气输出上限。当前档6继续为0.70m/s、2.00m/s²、2.00rad/s、12.00rad/s²；1:1直接XY＋相对旋转、不映射Z、无固定围栏。原600秒主机上限、630秒MCU上限及其他超时不改。
