# 4WS9 独立分档连续伺服候选

这是离线准备，不是实车性能或电气验收。不得用旧4WS7刷后记录授权新镜像。
一个独立镜像包含七档，默认未使能、未选档；可在后续只刷一次，每次启动入口固定一档，禁止运动中换档或自动升级。
原矩形、ESP32、Tenda设置、现用4WS7镜像及入口均不修改。

## 迁移与隔离

- 保留已验收的ContinuousSession：不做位置低通，40ms源时间速度估计、速度前馈、位置纠偏。
- MCU采用单个SI矢量斜坡，正常轮速不再叠加旧800cps/s独立慢斜坡；20ms编码器反馈滤波。
- 过零/反转每轮独立撤能、实测中性30ms后重新加入；750ms反转截止不能被抖动刷新。启动助推仍最多30%。
- 新4WS9/v4/184字节身份、独立档位选择字与逐档HMAC域；旧控制器、新低档不能悄悄接纳高档输出。
- 1:1 XY映射，杆Z不驱动小车；固定原起点前/左3×3m目标区，四边50cm物理缓冲、额外20cm裕量及车体轮廓不变。
- 目标边界限幅，不把缓冲当目标区域。松键、失焦、遮挡、姿态跳变/抬起/倾斜、通信/签名/来源冲突、堵转/反向反馈、急停保持保护。
- PC控制50Hz、MCU轮控100Hz、生产遥测10Hz；不宣称摄像机曝光到电机的硬实时延迟。
- 600ms底层命令租约、120s主机会话、150s底层预算、单次5s悬空预算不放宽；恢复必须松键、停稳、明确重新准备，真实MCU故障不能软清除。


入口固定ROS域119和/wand_4ws9_staged，Vicon源只读域0。两个入口与旧程序互斥占用同一真实UDP接收端口。
目前所有配置和复核模板均为NOT_APPROVED，默认命令不打开操作台或UDP。
日后实际启动必须显式`--launch --stage N --flash-record 实际记录 --trial-review 人工复核文件`，并在终端完成当次现场确认；没有自动使能。

## 后续刷写及逐档验收顺序

1. 获得新的刷写授权，确认电池断开且ST-Link接好；先完整读取1MiB Flash，记录哈希、板卡身份、选项字节和回退路径。
2. 仅写独立4WS9镜像，再独立完整读回1MiB；比较镜像有效段和读回哈希。此源码中没有烧录入口。
3. 断电拔ST-Link、接Tenda；固定四轮悬空。只在新固件上做必要的首档身份/单次短动作确认，不重复旧版本已经完成的排障。
4. 在新的、人工确认的独立会话逐档验证八方向、连续换向和松键；任何异常不升级。不必为换档再次刷写。
5. 各档落地前单独验证停车包络与供电负载，不把悬空顺畅等同于1.4kg实车的加速、制动和电气资格。
6. 记录实际Sign/车体同时间位姿、请求/实际轮速、饱和、停车时间/距离，复验遮挡后不自动恢复及人工恢复。

当前普通万用表未取得动态电压/电流/温升记录；旧悬空轮子顺畅仍有效，不强制重复那轮角度不便的电压测量，也不填写电气通过。
普通万用表可作为直流压降初筛，但不能证明峰值电流、再生尖峰或温升合格。不要把电流档并接电池。

**高档地面入口尚未放行**：逐档复核必须引用同一4WS9镜像上一档的人工审核实测证据，且本档停车包络须包含600ms失联后备撤能延时及车体/裕量。
0.70m/s在600ms内仅延时行程已是0.42m，尚未加实际滑行；50cm缓冲绝不是天然够用，2.00m/s²是正常命令加速度而非已测制动能力。
如果测得的包络放不进现有空间，应停止提速，再单独评审更短后备租约或场地方案；本候选不悄悄缩减安全余量或扩大区域。
由于本档包络尚未测得，本入口也不允许直接把常规Sign演示当作首次高速制动试验；受控停车试验需另行安排授权与独立场地预案。

## 复现离线准备

在ROS Jazzy和现有工作空间环境中运行`run_prepare.py --output 一个不存在的新目录`。
包含ASan/UBSan真实控制器故障注入、逐档主机/协议/监督器回归、私有Xephyr模拟按键和编码器的UI流程、独立ARM与ROS包构建、原矩形回归及519个原有文件哈希核对。
私有UI测试不读取真实按键、不启动真实ROS节点或UDP；仿真不含电流、热、轮胎/地面等真实动力学保证。
