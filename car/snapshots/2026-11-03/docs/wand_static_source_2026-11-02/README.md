# 后台600秒静止耐久修正版

本版独立于已保存的演示与矩形入口；不修改STM32、ESP32、Tenda、Vicon接收器或运动参数。

## 修正范围

- 原始Sign位姿与五个点用有界32深度队列保存同帧队列，不再让各个单深度订阅互相覆盖不同帧。
- 每次限时消化一批回调，避免只处理一条消息导致积压；同帧姿态计算采用不可变缓存。
- 来源身份检查与数据接收分开运行；查询耗时、回调数量、组帧数、丢弃未用旧帧等加入TRACE中的source诊断。
- 监督器和末级门的DDS身份查询同样移出控制回调；主执行器只消费有时限的查询结果，不由查询线程更新权限或控制时钟。身份冲突与查询失效仍撤权。
- 尚未被控制器选中的过期输入被丢弃，不更新时间戳。已经验证过的缓存自然过期不再冒充新的几何错误。
- 当前定位、已经选定的指令绑定帧仍按原200ms保护检查；几何错误、混帧、未来时间戳、身份冲突仍拒绝。不填补假位姿、不自动恢复运动。
- 位置完全不变但时间戳持续更新的帧仍是有效定位，没有“静止超过几分钟就结束”的规则。

## 启动与停止

仅在 `prepared_v1/QUALIFICATION.json` 通过、现场条件当前满足且有人可立即断电时，由操作员执行：

```bash
bash /home/PRIMARY_USER/vicon_mecanum_ws/tools/start_car_standalone_stable.sh --launch --site-ready --operator-trial --seconds 600
```

自检通过后在网页READY时单击空格开始；再次空格、Esc或停止按钮结束。已开始后切换界面/最小化继续，关闭或刷新页面仍停车。后台需要另开终端停车时：

```bash
bash /home/PRIMARY_USER/vicon_mecanum_ws/tools/start_car_standalone_stable.sh --stop
```

原入口 `start_car_standalone.sh` 保留不变，不会自动调用本修复版。不要同时启动两个小车运动入口。

## 验证与边界

完整实时600秒静止耐久使用独立ROS域197的模拟Vicon原始话题、ROS域196的实际监督器/末级门/桥接节点及专用回环端口的原生C固件模型，不连接实车。另测先运动再静止、120ms输入停顿、来源查询120ms迟到和真正Sign断流/几何错误的停车。

最终结果见 `prepared_v1/QUALIFICATION.json`。软件回归通过不等于真实Tracker已经连续输出10分钟或实车完成10分钟验收；这两项需现场复验。如果真实定位确实超过200ms没有有效新数据，仍必须停车，不能为了倒计时跑满而继续用旧定位。

## 保留的开发失败记录

`prepared_v1/short_motion_1` 暴露来源查询间隔加查询耗时超过窗口的问题；`prepared_v1/static600_1` 是并行浏览器回归期间约143秒触发控制循环超时的首轮失败记录，未作为通过证据。此后修正了查询调度，并将最终600秒耐久与故障注入串行执行；最终报告会明确列出实际通过的那一轮，不能用前面短程测试代替完整600秒。
