# 真实Sign → 独立ROS输出链 → 软件车

2026-10-29。独立仿真入口，不替换原演示，也不生成硬件许可。

## 使用

保持实车电池断开；使用原配置的唯一、已核验Vicon接收器。默认只检查文件：

```bash
bash /home/PRIMARY_USER/vicon_mecanum_ws/tools/start_fast_follow_ros_sim.sh --check
```

通过后打开真实Sign驱动的**软件车**：

```bash
bash /home/PRIMARY_USER/vicon_mecanum_ws/tools/start_fast_follow_ros_sim.sh --launch
```

窗口1280×720、较大字体。拿稳Sign，点击“准备”→等READY→单击空格开始；再次空格或Esc停车，松键本身不停车。切出窗口、界面心跳中断、定位/反馈失效也撤销输出。遮挡后返回数据不会自动走；停稳、消除原因后显式点击“确认并重新准备”，再用新空格动作开始。硬故障不得用准备按钮清除。

## 隔离与复用

- 域0只订阅Sign刚体及五个标记点；没有域0命令发布器、控制服务或实车反馈使用。
- 域189、本机发现、每次随机命名空间：同帧包→监督器→原来源摘要/时间戳校验→独立末级门→每次随机密钥签名输出→软件车。软件车不订阅裸`Twist`。
- 复用上一轮`FastCatchupSession`及其速度/加速度限制。复用独立开发的ROS有界参考帧历史/FIFO修复，仅通过本候选导入，不写入原包。
- 模型反馈、模拟车位姿与签名验证均实际经过ROS消息回调；这比同一函数里的纯模型演练多验证一层DDS链路，但仍不是物理电机、MC-Link、无线或固件验收，也不是跨进程压力认证。
- 1:1平移及相对旋转，Z不映射；沿用保存基线的无固定围栏策略。0.70m/s、0.80m/s²、0.10rad/s、0.40rad/s²、400RPM与120秒不变。
- 定位200ms、命令100ms、租约150ms、反馈300ms、界面调度100ms等原保护不变。拒绝旧帧刷新、错位姿、错摘要、错车体时间戳、未知FIFO头、篡改/重放签名、重复源。

“手动重新准备”仅在本软件仿真中创建新安全会话，保留模型位置/余速、逻辑发布者和单调命令序号，并拒绝旧队列序号。没有把旧实车已消费会话自动复位的逻辑移植到原演示。

## 验证记录

`docs/wand_fast_follow_ros_sim_2026-10-29/PREPARED.json`固定输入、候选、238个原文件及真实ROS测试报告哈希。未通过真实ROS回归或文件变化时拒绝启动。

单元回归覆盖六路同帧、重复不续龄、姿态几何/未来帧、Z处理、签名重放/过期/异主/超速/裸命令、真实Tk绑定和自动重复。准备流程修复版增加了两阶段就绪、按钮状态、过期操作和失焦回归；最终计数和通过状态以`PREPARED.json`及其固定的报告为准。

每次真人会话目录包含`CONTRACT.json`、`RECEIVER_PROVENANCE.json`、`events.jsonl`、`snapshots.jsonl`及正常结束后的`SESSION_RESULT.json`。原始六路包、所选摘要、模型反馈和门控状态可复核。运行中记录可能尚未缓冲落盘，不把缺少结尾当作完成验收。

需要真人实际做完快速手势/换向、Esc停车，以及遮挡停车/露出不自动恢复/显式重新准备/新空格跟随，才把真实Sign验收从“待完成”改为“完成”。合成故障测试不替代真实遮挡。

## 准备流程修复

- 准备是两阶段：连续健康/停稳→监督器预备→独立末级门确认；末级门未确认时不得写READY，也不能按开始按钮。
- Sign无完整新帧、输入异常、模型未停稳时，准备按钮禁用并显示中文原因，不先重置会话再给出泛化的英文超时。
- 等待中重复点击不延长5秒准备期限；已经READY时重复请求不重抓原点、重置会话或触发运动。
- 未准备/已停稳时失焦不制造新的STOPPING；准备/READY/ACTIVE失焦仍取消授权，并明确记录为失焦而非Esc。100ms界面、命令保护不变，过期操作只报告拒绝，不延迟补执行。
- 准备期间Sign丢失即取消；数据恢复不能自动准备或开始。停稳并人工重新准备后，仍需新空格动作。
- 每个UI操作的类型、年龄及拒绝原因会记入独立会话日志，便于区分按钮未可用、旧操作过期与真正的定位故障。

`prepare_probe.py`是供开发验收使用的真实Sign→软件车**零速准备**检查，明确不发送开始动作；它不是实车入口，不能用它替代真人动作验收。
