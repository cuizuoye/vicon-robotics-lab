## 纯软件浏览器排练

```bash
bash /home/PRIMARY_USER/vicon_mecanum_ws/tools/start_car_4wsc_browser.sh --rehearsal --stage 0 --seconds 60
```

使用合成 Sign、独立进程运行的原版 C 控制器和未辨识的软件编码器模型；实际启动 ROS 监督器、末级门和独占 UDP 桥，但只准连接专用 `127.0.0.1` 端口。DDS 为独立域 192、随机命名空间，不能借此接入真实 ESP32。网页应显示“回环软件排练／无实车输出”。

自检后打开网页，自动准备；显示 READY 后，按一次空格开始，再次空格或 Esc 停止，松开空格不停。页面失焦、隐藏、控制/画面断连、输入证明超时都会撤权，本轮结束后不自动恢复、不重复准备；关闭本轮再重新启动。网页只显示蓝色小车和橙色 Sign 的 1:1 原始目标，无绿色中间参考点。

可用 `--purpose suspended --seconds 5` 排练悬空专用模式：先轻按并松开空格解锁、自动准备且不转轮；READY 后**按住**空格，松键停，最长 5 秒，本窗口只运行一次。不要把悬空模式与落地单击模式混淆。

## 后续真实接入顺序（当前不执行）

1. 用户确认接线、动力状态并授权后，先只读核对实际连接。ST-Link 仍连接、MCU 内核暂停时不能把握手未就绪误诊为无线故障；本次程序不会代替用户复位或运行真实应用。
2. 第一项实际网络测试使用 `--idle-probe`，只发 HELLO 和失能零速；不选档、不使能、不清故障、不运行 ROS。需要明确接口、ESP 地址和当前配置文件 SHA；探测只能报告实际故障，不能为了就绪自动清锁存。
3. 失能握手、4WSC/8/208 身份、ACK 时钟、原始反馈、无故障及零输出通过后，现场复核并显式批准**档 0、悬空用途**。首次只做一轮 5 秒、四轮固定悬空、有人能立即断电。当前没有任何已批准的真实运动配置。
4. 逐档验收须记录当前镜像、档位、用途、实际动作/停车和人工复核，不沿用 4WS8、4WSB 或仿真结果作为新 4WSC 的物理通行证。落地 Sign 跟随另需停车包络、电气和温升复核。现有落地准入保留 0.50m 停车包络审查（包含 600ms 失联回退与车体外廓）；高速档可能无法满足，届时必须实测并重新讨论缓冲，不绕过检查。

### 仅失能零速探测命令模板

以下为安排接线之后使用的模板，**现在不要执行**；`ENDPOINT.json` 可取档 0 草稿中已核对的硬件地址/接口（必须核对而不是自动假定）。不需要也不得伪造运动审批。

```bash
bash /home/PRIMARY_USER/vicon_mecanum_ws/tools/start_car_4wsc_browser.sh \
  --idle-probe --profile /绝对路径/ENDPOINT.json \
  --profile-sha 已核对文件的SHA256 \
  --consent 4WSC_DISABLED_ZERO_ONLY_NO_ENABLE_NO_CLEAR --seconds 8
```

真实运动入口需要 `--launch --stage 0 --purpose suspended`、精确批准的配置文件与哈希、对应用途同意串。未批准的 `profiles/*.NOT_APPROVED.json` 会在 ROS、硬件 socket、网页构建前拒绝，不能直接作为启动命令。

## 离线证据的正确解释

- 使用真实 ROS 节点、真实签名输出和独占传输代码，加原版 native C 控制器，并不等于跑过真实 STM32、无线链路或电机。
- 浏览器协议测试包含 60 秒连续运行，以及未开始、输入超时、画面断开、控制断开、再次空格、随机数重放、越权目标和遮挡；协议对等端不是浏览器 UI 自动化，实际网页检查另行注明。
- 反馈中断时门控置零、MCU 模型撤权；恢复后不自动续跑。失去可信反馈不能伪称已经物理停稳，保留 `STOP_UNCONFIRMED`。
- 初期失败记录包含配对反馈未同时前进、健康历史预算导致无法二次准备、软件代理与 ROS 共用线程造成的排队、悬空正常结束误标故障等。修正仅进入独立 4WSC 主机副本，未改变真实固件、旧入口或超时阈值；所有失败记录保留。
