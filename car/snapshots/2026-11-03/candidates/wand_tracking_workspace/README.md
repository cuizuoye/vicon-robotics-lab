# 无固定围栏：独立4WS8电脑端入口

这是现有电脑端平移＋旋转控制的独立副本，不刷写STM32/ESP32，不迁移4WS9固件，不改变旧的矩形/平移/旋转入口和网络设置。

取消的空间限制：固定目标矩形、车体固定边界、目标限幅、4.75米位移半径、绿色区起点及保存朝向检查。不是把围栏改成一个很大的矩形。原几何数字仅作为历史校准元数据保留，不能代表已测量的新覆盖区域。视图自动缩放也不是围栏。

保留：位移/相对转角1:1、启动使能边沿记录原点、0.70m/s与0.80m/s²、4WS8原有0.10rad/s与0.40rad/s²角参数、120秒单次会话、空格/Esc/停止、失焦停车、来源摘要与时间戳独立校验、200ms小车/Sign定位和底层反馈超时、100ms命令超时、150ms租约、100ms控制间隔、抬车/倾斜/位姿跳变、跟踪误差、无进展、执行器故障、600ms底层看门狗、150秒底层上限、异常不自动恢复。松开空格本身不停车。

不承诺“只要Vicon看得见就绝不会停”：上述动态保护仍可停车。也没有障碍检测或实测Vicon覆盖多边形；遮挡/丢失发生后仍有处理和停车距离，不能把定位丢失边缘当作物理防撞边界。首轮需要人工检查实际路径及停车余量，并有人能立即断电。

默认仅核验文件，不初始化ROS或连接设备：

```bash
bash /home/PRIMARY_USER/vicon_mecanum_ws/tools/start_car_tracking_workspace.sh --check
```

离线准备与验证通过后，现场确认时才打开此独立入口：

```bash
bash /home/PRIMARY_USER/vicon_mecanum_ws/tools/start_car_tracking_workspace.sh --launch
```

此命令会依照原配置检查/恢复Tenda独立链路、复用或启动只读Vicon接收；本轮开发没有执行它。现场三项勾选后自动打开并准备，但不自动运动。必须看到READY，再轻按并松开空格才开始；再次空格/Esc停止，最长120秒，一次会话用完不能自行续跑。原“小车演示”命令保持原来的有围栏版本，便于回退。

检查沿用原4WS8完整刷写读回证据，并不代表本轮重新读过芯片。真正连接时仍会核验实时固件标志、时钟与失能零速握手；若板内已更换4WS9，此入口必须拒绝，不伪造旧身份。

验证分三部分：纯控制器+独立末级门的连续8米跟随；真实ROS节点在域187/LOCALHOST，使用软件Sign/软件Plant进行旧围栏外起步、长距离及故障注入；私有Xephyr中检查1280×720大字界面。ROS软件源使用20Hz和订阅发现屏障，测试空间策略与失效停车，不作为100Hz实际Vicon链路性能认证。原始报文来源、真实驱动板电气、实车制动距离与全场地覆盖仍须现场验证。

调试草稿均保留。`draft_04`记录了ROS软件源发现初期缺帧，未通过；`draft_05`记录了软件Plant积分时间与20Hz节拍不匹配，未通过。`attempt_06_incomplete_positive_assertion`曾错误地把“注入前已被参考连续性保护停下”的长程平移＋旋转用例算作通过；该汇总不作为最终证据。最终脚本增加注入前必须持续ACTIVE、末级门无故障的断言，长程围栏穿越单独使用纯平移输入；短程组合平移＋旋转仍单独覆盖。已有参考连续性保护未移除、未放宽，未把它当作围栏处理。
