# 无级调速实验与固定基线迁移说明

本轮不刷写、不启动实车、不更改ESP32/Tenda。固定浏览器基线、旧矩形和全部封存证据保持不变。

## 两条独立交付线

1. 冻结目前直接Sign固定参数的软件基线，准备独立4WSC STM32能力镜像。固定基线仍是后续实机迁移对象；无级调速实验不自动覆盖它。
2. 基于同一1:1直接目标，制作独立无级调速软件候选。先做确定性回放、故障回归、真实ROS签名输出链和浏览器合成手势验证；真实Sign的人手体验、实车表现仍待验收。

“同步最好”在此指现有证据支持的候选，不宣称所有动作、模型或硬件上全局最优。最新直接基线的人手真实Sign运动体感仍未单独复验；它已有真实手势记录回放、ROS合成输入及浏览器验证。

## 开源依据（2026-10-30检索）

- [ArduPilot AP_Math/control.cpp](https://github.com/ArduPilot/ardupilot/blob/master/libraries/AP_Math/control.cpp)：公开平方根误差校正、速度前馈、相对闭合运动及加速度整形的实现。这里只参考数学结构，独立写项目实现；没有把整套飞控控制器移植到小车，也没有以飞控成熟度替代本车验证。
- [Nav2 Velocity Smoother](https://docs.nav2.org/configuration/packages/configuring-velocity-smoother.html)：明确区分最大加速度/减速度、共同缩放，以及命令状态和里程计反馈两种工作方式。借鉴其明确约束边界，但不额外串联一个平滑器，不增加第二条正常加速斜坡。
- [Ruckig官方README](https://github.com/pantor/ruckig#tracking-interface)：普通逐点位置轨迹跟踪任意移动信号会落后；专用Tracking接口属于Pro。此轮不增加Ruckig依赖、不使用Pro功能、不用云端计算，也不重新制造绿色中间轨迹。

这些来源支持算法结构，不支持“本候选已被上述项目验证”或“实车达到仿真加速度”的结论。

## 控制链与公式

原点在首次有效零速ACTIVE时捕获。目标保持：

`p_target = p_car0 + p_Sign - p_Sign0`

`yaw_target = yaw_car0 + unwrapped_yaw_Sign - unwrapped_yaw_Sign0`

Z不映射；没有中间位置参考、超前半径或电子围栏。“离得远”指目标与车的追踪误差，不是人和车在场地中的实际间距。

使用40ms因果窗口估计Sign平移/转角速度，保留原始时间戳及60ms前馈失效限制，不外推位姿、不刷新旧帧。速度需求由手速前馈＋位置校正组成。标定杆收回时目标仍收回；并非只跟手速不管绝对误差。

位置校正近区线性，远区由制动距离形成平方根形状：设误差幅值r、增益k、加速度边界a，连接点为a/k²；连接点以内为kr，以外为`sqrt(2a(r-a/(2k²)))`。方向沿误差向量，转角同理，并防止单个数值步长超过剩余误差。这只是速度需求计算，不生成另一个移动目标。

加速度预算连续调度：

`S(q) = 3q² - 2q³, q = clamp(value / threshold, 0, 1)`

`a_normal = a_min + (a_max-a_min) max(S(position_error), S(hand_speed))`

选定软件实验参数：

| 项目 | 平移 | 旋转 |
|---|---:|---:|
| 连续加速度预算 | 1～4m/s² | 1.5～12rad/s² |
| 误差达到完整预算的尺度 | 0.30m | 0.50rad，约28.6° |
| 手速达到完整预算的尺度 | 0.70m/s | 1.20rad/s |
| 绝对速度上限 | 1.20m/s | 2rad/s |

这里预算不等于每时刻实际加速度：需要加速才使用预算，跟上并稳定匀速时加速度可以为零。近目标但必须制动或反向时，采用相对命令速度的制动需求，可提高预算到硬上限，避免为了柔和而削弱必要停车。该估计基于命令状态，不假装测到了真实轮速；物理模型误差待实车辨识。

近区增益最高4/s，远区回到原平移1.4/s、旋转2/s；平移与转角误差共同降低额外增益，避免严重饱和时互相争抢轮速。所有参数连续变化，不在运行中切换固件档位。

最后只应用一次有效共同轮速/速度/加速度约束。四轮共享381.97RPM预算，纯45°斜向最高约0.849m/s；旋转也消耗同一预算。无法靠算法在不改变硬件能力的前提下无限快追上超限手势。

## 稳定性和结果边界

19项针对性回归覆盖连续/单调调度、快速手势、近目标制动、换向、1:1目标来源、动态与绝对限幅、遮挡/反馈/租约丢失、无进展、噪声、准备后调整杆与停车。原定时、源身份、独立门、签名、防重放及撤权机制保留。

`BENCHMARK.json`是第一轮固定高增益筛选，保留其极快混合手势退步。`BENCHMARK_V2.json`加入远区增益回退，`BENCHMARK_V3.json`再加入平移/旋转误差共同调度；不删除失败/较差试验，也不把平均分改善等同于所有场景改善。

最终同输入τ=0.12s数学模型结果（每条轨迹末尾增加6秒保持），误差为目标与数学车的RMSE，不是物理延迟：

| 场景 | 固定基线平移RMSE | 无级候选平移RMSE | 固定基线/候选转角RMSE |
|---|---:|---:|---:|
| 慢手势 | 0.794cm | 0.463cm | 0.00710 / 0.00613rad |
| 快速往返换向 | 5.95cm | 3.46cm | 0 / 0 |
| 约6m×5m全向轨迹 | 2.34cm | 1.63cm | 0 / 0 |
| 变频大角度旋转 | 0 | 0 | 0.07372 / 0.05142rad |
| 大范围平移＋旋转 | 4.43cm | 2.45cm | 0.03371 / 0.02431rad |
| 之前约290秒真实手势目标回放 | 25.76cm | 26.80cm | 0.32053 / 0.32789rad |

最后一行平面误差约退步4.0%、转角约退步2.3%，包含超出输出能力的快速混合动作。该结果虽在本轮预设5%逐项筛选容差内，仍不能称为全面优于基线，因此保持实验入口，不替换固定基线、不晋升为实机版本。

真实ROS使用独立签名作用域、同原始Sign报文/小车时间戳绑定和数学执行器。`ROS_PROTOCOL.json`记录9项真实ROS合成协议流程，普通流程74秒；其对端不是浏览器。实际浏览器启动、动画与Esc停车另保存截图和会话结果。真实Sign运动体验、真实反馈延迟、停车距离、电流和温升均未由这些测试证明。

本轮实际浏览器合成手势会话：`prepared_v1/sessions/fast_software_1CV3is`完整运行60秒，TIMER_COMPLETE并STOPPED_CONFIRMED，最大UI间隔24.5ms、证据年龄37.7ms，数学停车确认约0.835秒；`fast_software_ccPF1g`由浏览器按Esc结束并确认停车。其画面与日志分别保留，未以协议测试对端冒充浏览器、未触达实车，也未放宽100ms门限。ROS中实际记录到3055条有连续加速度预算的有效ACTIVE状态，范围1～4m/s²，目标始终等于原始1:1映射目标。

## 使用与后续

固定基线：`bash /home/PRIMARY_USER/vicon_mecanum_ws/tools/start_sign_browser_direct.sh`

独立无级软件候选：`bash /home/PRIMARY_USER/vicon_mecanum_ws/tools/start_sign_browser_adaptive.sh`

二者都只有软件车，不是实车指令；保持实车断电/未连接，不能同时运行。固定基线不变，准备后按一次空格启动、再次空格/Esc停止；松键不停车，窗口失焦仍撤权。

后续优先补齐4WSC配套实机浏览器的固件身份/档位准入和离线链路联调，再联系用户连接ST-Link，按完整备份、刷写、读回和从低档开始的流程迁移。不能拿此软件仿真入口直接向实车发动作。
